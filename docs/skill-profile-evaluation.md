# 单个 Skill 的能力报告与同类对照

## 判别器如何回答一个链接

| 问题 | 展示与判定依据 |
| --- | --- |
| 规模多大 | `SKILL.md` 的 Unicode 码点数和正文码点数，均计入原文的换行。导出的数据另列 UTF-8 字节、已读文本总字符数及文件清单范围。 |
| 能做什么 | 从名称、用途和正文定位可识别的动作。在 PDF、电子表格和工位任务上提供具体能力条目。其他用途可从说明章节与用途查看。否定句和代码块内的示例标题不作为能力声明。 |
| 做得怎么样 | 有实验时报告通过数、分母和失败条件。已读文档可以展示声明。当前版本没有对应实测时保留待验证。 |
| 为什么评成这样 | 每条说明依据指回原文；包中已确认问题可定位到对应文件或接口；实验报告列出版本、验收条件和案例产物。 |
| 和同类相比怎样 | 固定对照版本提供长度、同规则说明覆盖、任务侧重和可共同复跑的数据。还可添加任一公开对照链接。仅在同条件实测可匹配时比较通过数。 |

“说明覆盖”是七项规则命中数。规则查找名称与用途、输入、输出、步骤、验收、限制、运行环境。每项显示定位到的文本或“本次规则未找到”。推断来自规则匹配，可能漏掉同义说法，也可能把相关表述识别为说明线索。字符数和命中数从未用于推断功能通过率。

已有配对结果时优先用留出输入下结论。至少 8 项、通过率达到 90%，且已登记功能组均达到 75%，判为“优秀（在实测范围内）”。总体低于 50% 判为“表现欠佳”，其他有结果的范围判为“有条件可用”。已确认的包缺陷或明确不具备的运行条件优先显示。局部复跑只评价对应的步骤。阈值是当前产品规则，尚无跨领域校准。

## 工位编码 Skill 的真实模型产物

固定版公开说明的字符数和能力可从试用页面查看。实验用 DeepSeek Flash 在 32 组相同输入上分别不读、读入该 Skill，输出由登记的精确匹配规则检查。

| 输入组 | 无 Skill | 读入 Skill | 能力边界 |
| --- | ---: | ---: | --- |
| 常规单一匹配 | 8/8 | 8/8 | 单一合法匹配在本批上均通过 |
| 同词在不同工位 | 7/8 | 8/8 | 在本批中改善一项 |
| 同工位多码 | 0/8 | 0/8 | 期望输出 UNKNOWN，记录中出现了选中一个合法候选的行为 |
| 无合法匹配 | 0/8 | 0/8 | 期望输出 UNKNOWN，记录中出现了填入实际编码的行为 |
| 全部 | 15/32 | 16/32 | 净改善 1 项 |
| 留出 | 8/16 | 8/16 | 当前留出输入没有观察到通过数改善 |

该版本在本任务契约下为“有条件可用”。验收只接受同工位唯一精确别名，遇到多个或零个候选须输出 UNKNOWN。原说明还允许某些近似情况按上下文选择候选，相关方法未在这些精确输入上验证。该实验使用的是局部任务规则和一套运行环境。

## 公开 PDF Skill 的同输入流程复跑

使用相同的本地库复跑审核过的默认选择。三者的文字步骤均使用 `pdfplumber` 逐页提取。Anthropic 和 Nous 的默认提表步骤都用 `extract_tables()`。四个文字任务检查逐页内容与顺序。六个表格任务检查目标表头、行数、行键及数据格值。未执行上游 Skill 包、调用模型、跑 OCR 或对图片进行目视验收。

| 固定公开 Skill | 逐页文字 | 默认网格提表 | 说明中可核查的侧重 |
| --- | ---: | ---: | --- |
| [Anthropic PDF](https://github.com/anthropics/skills/blob/e4bb5d960d87126ff3b3a8af1a104b7db67560ba/skills/pdf/SKILL.md) | 3/4 | 2/6 | 提表、布局文本以及扫描 OCR 有各自的示例 |
| [OpenAI PDF](https://github.com/openai/skills/blob/49f948faa9258a0c61caceaf225e179651397431/skills/.curated/pdf/SKILL.md) | 3/4 | 待测 | 强调先渲染页面，以及交付前的布局和视觉验收 |
| [Nous Research PDF](https://github.com/NousResearch/hermes-agent/blob/a15b9710395aa1c4858fb6dd9e4c5014c5ced4e9/skills/productivity/pdf/SKILL.md) | 3/4 | 2/6 | 提供 CSV 导出入口，并明确提示无框和合并单元格需要调参 |

三者的默认文字提取在双栏样本上交错输出，违反登记顺序。两种默认提表方法只通过了两个网格表，共核对正确 12/46 个数据格。

在同组六个输入上，判别器附带的表格流程增加目标表头、行数和版面提取，额外通过普通无边框表及论文表 6，合计 **4/6** 个任务、**40/46** 个正确数据格。脚注模拟例多出一行，即使其中的六个数据格正确，仍判未通过。跨列合并表也未通过。表头和预期行数取自固定任务要求，实际数据值只在提取后用于验收。

## 复查

原始 `SKILL.md` 通过固定公开提交读取。随包[流程记录](../src/skill_discriminator/data/skill-profiles.json)保存来源指纹、输入指纹、实际与期望输出。只有仓库、提交、文件路径、原始和分析文本指纹匹配，才把局部结果附到当前链接。

```powershell
python -m pip install ".[dev]" pdfplumber==0.11.11 reportlab==4.4.10
python scripts/profile_study.py --output reproduced-skill-profiles.json
python -m skill_discriminator.verify
python -m pytest -q
```

生成脚本需要读取固定公开版本，默认将文档缓存到 `tmp/profile-sources`。五个公开说明样本来自 PDF 和电子表格两类。XLSX 对比目前限于同规则说明覆盖、来源可定位的差异与实际运行条件。执行覆盖集中在登记的任务和公开步骤，无法由该对照推出任一平台的整包能力排名。
